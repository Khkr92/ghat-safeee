From hardware to software

The hardware GHAT-SAFE used IR or radar sensors at each approach, a microcontroller, and LED boards. The software version keeps the same three steps (Detect, Warn, Guide) but replaces every physical part with something that already exists: drivers' smartphones, CCTV cameras already on the ghat road, and a cloud service.

System architecture

Core algorithm (runs every second for each bend)

advisory   = ADVISORY[weather]                 // 25 / 20 / 20 km/h
SSD(v)     = v·t + v² / (2·g·f)                 // t = 2.5 s, f by weather
zoneLength = SSD(40 km/h) + v·2 s               // covers GPS + network delay

occA = vehicles heading A→B inside [bendStart − zoneLength, bendEnd]
occB = vehicles heading B→A inside [bendStart, bendEnd + zoneLength]

for each driver d inside their approach zone:
    oncoming = (d from A) ? occB : occA
    if oncoming vehicle already inside bend → HEAD-ON RISK : "Hold left, slow to 15"
    elif oncoming in its approach zone      → ONCOMING     : "Vehicle ahead, slow down"
    else                  → CLEAR         : "Drive carefully, max {advisory}"
    if d.speed > advisory + 5 → OVERSPEED : "Slow down, hairpin ahead"

log every alert, overspeed and near-miss for the dashboard

Software stack for the real build

  • Driver app: Flutter or native Android. Fused-location GPS at 1 Hz near bends, geofences stored on the phone so alerts still work in weak signal, text-to-speech in Telugu, Hindi and English.
  • Backend: Node.js or Python (FastAPI) with Redis for live bend state and PostgreSQL + PostGIS for bend geometry and logs. MQTT or WebSocket for sub-second push.
  • CCTV module: Python + OpenCV + a YOLO vehicle model on a small edge PC or the existing control-room server. Sends only counts and direction, never video.
  • Dashboard: Web app (this page is a working prototype of it) with bend ranking, overspeed share, and exportable reports for road-safety audits.

Limits to state honestly

  • Drivers without the app are invisible unless a camera covers the bend. Use the adoption slider to see this effect; at low adoption the CCTV module matters most.
  • Phone GPS is accurate to about 3–10 m and weakens under cliffs. It cannot tell which lane a vehicle is in, so the system warns about presence, not lane violations.
  • Mobile coverage on ghat roads is patchy. On-device geofences and the CCTV path reduce, but do not remove, this risk.
  • The app must never replace signs, chevrons, mirrors or barriers. It adds a layer on top of the standard measures from a road-safety audit.
  • Screen alerts can distract. Voice-first alerts and a locked, simple screen while moving are design requirements.

Pilot plan

  1. Map three to five crash-prone bends with the road authority and record their geometry.
  2. Collect two weeks of baseline speed and conflict data from CCTV, system off.
  3. Release the app to bus and goods-vehicle drivers first (high mileage on ghat roads, easy to reach through depots).
  4. Run four weeks with the system on and compare near-miss rate and overspeed share.
